# GraphRec SDKs

Client libraries for calling the GraphRec API from your own service. Designed in
[`docs/SDK_DESIGN.md`](../docs/SDK_DESIGN.md); this directory is that document,
implemented.

| | Package | Import | Runtime |
| --- | --- | --- | --- |
| [`typescript/`](typescript/) | `@graphrec/sdk` | `@graphrec/sdk` | Node ≥ 20 |
| [`python/`](python/) | `graphrec-sdk` | `graphrec_sdk` | Python ≥ 3.10 |

Both cover the same ten routes, raise the same error classes, and derive the same
two hostnames from the same options. Where they differ they differ in idiom —
`camelCase` and `Promise` on one side, `snake_case` and `async def` on the other
— and not in behaviour.

Two class names differ, and only because Python already has the good ones:
`TimeoutError` and `PermissionError` are builtins, so the Python package spells
them `APITimeoutError` and `PermissionDeniedError`. `from graphrec_sdk import
TimeoutError` would otherwise change the meaning of `except TimeoutError` in
code that has nothing to do with this SDK. The two also differ on one unit:
`timeout` is milliseconds in TypeScript, where `setTimeout` is, and seconds in
Python, where `time.sleep` and `httpx` are.

## Server-side only

Every call carries a `gr_live_` credential, which is a bearer token with
tenant-wide scope. There is no browser build of either package and there will not
be one; the shape that works is browser → your server → GraphRec. Each package's
README opens with the full reasoning.

## The contract these hold

Four things about the API drove most of the design, and each is checked by a test
rather than left to the prose:

- **Two hosts.** The control plane is one hostname for every tenant; the data
  plane is one hostname *per* tenant, because N3's edge resolves your replicas
  from the subdomain. No single base URL can express that, so nothing in either
  surface lets a call choose its host.
- **Bearer, not signed.** No canonical string, no `X-Signature`, no clock skew
  window. The HMAC in `graphrec/auth/api_keys.py` is at-rest hashing on the
  server, not something a client computes.
- **Idempotency is in the body.** `event_id`, `sync_id`, `batch_id`,
  `request_id` — yours, never generated by the SDK, because a generated one
  differs per attempt and would turn a retry into a second write.
- **One error envelope.** `class`, `code`, `reason`, `reference`,
  `field_errors`, `retryable`, `retry_after_seconds`, on every failure from
  either plane. The mapping from that envelope to a class is total in both
  languages, and both suites read the server's own source to prove it.

## Tests

Neither suite mocks the contract from memory. `test/routes.test.ts` reads
`frontend/openapi.json`, `test/config.test.ts` reads `deploy/n3/Caddyfile` and
`graphrec/serving_driver/compose.py`, `test/errors.test.ts` reads
`graphrec/common/errors.py`, and the Python suite reads the same files from
`tests/sdk/`. A change on the server that the SDK has not followed turns a suite
red in the same commit.

```sh
cd typescript && npm ci && npm run typecheck && npm test && npm run build
.venv/bin/python -m pytest tests/sdk          # from the repository root
```
